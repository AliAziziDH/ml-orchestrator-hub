# Local Testing with ngrok and FastAPI

This guide explains how to set up local testing for the Orchestrator's SMTP-to-HTTP webhook integration using `ngrok`.

## Prerequisites

1.  **FastAPI Server**: You need the orchestrator running locally. You can use `uvicorn` to start it:
    ```bash
    uvicorn orchestrator_core.gateway:app --reload --port 8000
    ```
2.  **ngrok**: Install `ngrok` if you haven't already ([https://ngrok.com/download](https://ngrok.com/download)).
3.  **HMAC Secret**: Ensure the `ORCHESTRA_HMAC_SECRET` and `CONDUCTOR_AUTHORIZED_EMAIL` environment variables are set correctly so that `process_inbound_webhook` can validate signatures.

## Step 1: Start ngrok

Start ngrok to expose your local port (e.g., 8000) to the public internet:

```bash
ngrok http 8000
```

ngrok will output a forwarding URL, such as `https://<random_id>.ngrok.io`. Keep this terminal window open.

## Step 2: Configure SendGrid

To route live test emails to your local instance, configure SendGrid's Inbound Parse Webhook:

1.  Log in to your SendGrid account.
2.  Go to **Settings** -> **Inbound Parse**.
3.  Click **Add Host & URL**.
4.  **Domain**: Select your configured receiving domain (e.g., `mrsaz7.com`).
5.  **Destination URL**: Paste your ngrok URL and append the webhook path: `https://<random_id>.ngrok.io/v1/webhook/email`.
6.  Ensure **POST the raw, full MIME message** is *unchecked* (we want the parsed format).
7.  Click **Add**.

## Step 3: Mock Testing with `curl`

If you want to manually test the endpoint locally without sending a real email, you can send a mock payload using `curl`.

Since the gateway restricts IPs to known Cloudflare/SendGrid ranges, you'll need to either allow `127.0.0.1` (included by default in the gateway) or simulate a request from an allowed IP using the `X-Forwarded-For` header.

### Simulating a SendGrid Payload

Save the following as `mock_payload.json` (replace the signature with a valid one generated by your system):

```json
{
  "dkim": "{@...}",
  "envelope": "{\"to\":[\"test@mrsaz7.com\"],\"from\":\"conductor@yourdomain.com\"}",
  "text": "APPROVE\n\nLooks good to go.",
  "headers": "In-Reply-To: <valid_hmac.thread_123.ckpt_456@orchestra.local>\nDate: Wed, 10 Aug 2023 10:00:00 +0000"
}
```

Send the request using `curl`:

```bash
curl -X POST http://127.0.0.1:8000/v1/webhook/email \
  -H "Content-Type: application/json" \
  -H "X-Forwarded-For: 104.16.1.1" \
  -d @mock_payload.json
```

**Expected Response (if HMAC is valid):**
```json
{
  "status": "success",
  "decision": "APPROVE"
}
```

**Note**: To successfully process a mock request, the `In-Reply-To` header must contain a valid cryptographic signature matching your local `ORCHESTRA_HMAC_SECRET`. You can generate a valid signature using the `email_signature_generator.py` script.
